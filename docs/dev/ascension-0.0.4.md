# Ascension 0.0.4 — Modern Experience

Status: **test candidate**. This branch starts from the manually accepted `checkpoint/2026-09-15-watch-fixed` state. The checkpoint remains the recovery baseline and is not rewritten by this release work.

0.0.4 is intentionally being qualified in layers: automated Windows/MSYS2 + Linux GCC 13/14 integration first, then real-device playtesting on Windows. A green compiler does not replace a real-controller feel test.

## Release intent

0.0.4 turns the already-proven Modern mouse/Q Watch work into a coherent PC-controls release without disturbing the parts that were accepted in manual play.

The release adds:

- Modern controller-0 twin-stick mode;
- radial left/right stick deadzone;
- Linear and Precision right-stick response;
- independent gamepad look sensitivity and ADS scale;
- independent gamepad X/Y inversion;
- Southpaw stick layout;
- optional LT/RT fire/aim swap;
- analog left-stick movement through GoldenEye's existing `analogStrafe` and `analogWalk` channels;
- frame-scaled right-stick camera look through the existing V3 PORT camera bridge;
- a familiar Modern face-button layout while Classic/Hybrid keep their legacy path;
- live keyboard rebinding inside `F10 -> Controls` using the existing `Input.Bind.*` config keys;
- live Modern gamepad button rebinding inside `F10 -> Controls` using `Input.ModernPadBind.*`;
- a Universal Controller Layer in front of V4 so physical controller quirks are normalized before gameplay sees them;
- SDL2/XInput/HID gamepad mappings as the preferred zero-heuristic path;
- optional loading of the community SDL_GameControllerDB from `gamecontrollerdb.txt` or `data/gamecontrollerdb.txt`;
- a conservative fallback mapper for otherwise-unknown generic USB gamepads;
- explicit user controller-map overrides through `data/ascension-controller-mappings.txt`;
- hot-plug, unplug and controller-remap handling without requiring a game restart;
- packed logical controller slots so skipped raw devices cannot shift controller 1 into the wrong GoldenEye channel;
- one canonical prepare/test/build/play entry point: `tools_pc/ascension.py`;
- Windows and Linux GCC 13/14 CI for the complete stack, including retained regression/build logs.

## Universal Controller Layer

The universal layer sits **before** Modern Controls V4:

```text
physical device
    |
    +-- SDL2 built-in / XInput / HID mapping
    |
    +-- optional SDL_GameControllerDB mapping
    |
    +-- conservative generic-gamepad fallback
    |
    +-- explicit user override mapping
    v
normalized SDL_GameController
    v
Modern Controls V4 / Classic / Hybrid
    v
GoldenEye
```

That boundary is deliberate. V4 still owns Modern stick shaping, camera response, ADS scaling and button semantics. The accepted mouse path still owns mouse input. The Universal Controller Layer does not implement a second gameplay-control model.

### Mapping priority

When several mapping sources can describe the same controller, later sources override earlier ones:

1. `data/ascension-auto-mappings.txt` — low-priority mappings generated by the conservative fallback;
2. root `gamecontrollerdb.txt` — optional community database;
3. `data/gamecontrollerdb.txt` — optional community database downloaded by the developer helper;
4. `data/ascension-controller-mappings.txt` — explicit user corrections, highest priority.

`tools_pc/update_controller_db.py` downloads a **pinned** SDL_GameControllerDB revision rather than mutable `latest` data. Runtime does not require network access. `python tools_pc/ascension.py play` performs this update as best-effort only; if it cannot download the file, SDL's built-in mappings and the local generic fallback remain available.

### Unknown generic controllers

A truly unknown HID device cannot have its semantic layout inferred with certainty from raw axis/button numbers alone. Ascension therefore uses a conservative fallback rather than pretending every USB HID is an Xbox controller.

The fallback is considered only after SDL/community mappings fail. It requires at least two axes and four buttons, records the controller GUID, axis/button/hat counts and name, and maps a common DirectInput-style layout. Devices that do not look sufficiently gamepad-like remain raw and are not hijacked; this reduces the risk of claiming a wheel, pedal set or HOTAS as a gamepad.

If the fallback mapping is wrong for unusual hardware, place a correct SDL mapping in `data/ascension-controller-mappings.txt`. That explicit mapping outranks the generated fallback on the next launch/rescan.

### Controller identity and slots

Recognized physical controllers are packed into contiguous GoldenEye controller slots. The log records:

- logical controller slot;
- SDL physical device index;
- reported device name;
- detected family (`XBOX`, `PLAYSTATION`, `NINTENDO`, `8BITDO`, `STEAM`, `LOGITECH` or `GENERIC`);
- SDL joystick GUID.

This fixes the old sparse-index behavior where an unrecognized physical device before a valid controller could leave `pads[0]` empty and accidentally place the playable controller in a later slot.

## Deliberate non-changes

0.0.4 does **not** redesign or replace:

- the accepted Modern mouse direct-look math;
- native frontend mouse pointer behavior;
- Q Watch ownership or stock Abort Mission semantics;
- F10 quick-return semantics;
- mission availability/save isolation;
- collision, AI, weapons or mission logic;
- ROM text/assets;
- Classic or Hybrid gameplay semantics.

If one of those changes while testing 0.0.4, treat it as a regression.

## Modern gamepad contract

With `Input.ControlPreset=2` and `Input.ModernGamepad=1`:

- left stick: analog strafe + walk;
- right stick: direct camera look;
- RT: fire;
- LT: aim;
- A: action/use;
- X: reload/cancel;
- B: dedicated crouch through GoldenEye's native aim+down posture gesture;
- Y: next weapon using the native inventory edge;
- LB: previous weapon using GoldenEye's A+Z reverse inventory chord;
- RB: native L/alternate action;
- Start and D-pad retain their native mapping.

The V4 path is scoped to controller 0 because the PC mouse/keyboard Modern experience is also player-1 oriented. Local multiplayer controllers continue through the legacy N64 gameplay mapping after device normalization.

`Input.ModernPadSouthpaw=1` swaps the movement and camera sticks without changing game logic. `Input.ModernPadSwapTriggers=1` swaps the LT/RT aim-fire roles without changing their analog trigger behavior.

## Radial shaping

`Input.ModernPadDeadzone` is a radial percentage rather than separate X/Y gates. Input inside the circle is zero. Input outside it is rescaled back to the full 0..1 range so the deadzone does not reduce maximum speed.

`PRECISION` applies a mild power curve after the deadzone; `LINEAR` leaves the rescaled magnitude linear. Direction is preserved in both modes.

## Keyboard rebinding

Open `F10 -> Controls`, select a `Bind:` row, activate it with Enter/right/LMB, release that activation key, then press the new key. Escape or F10 cancels capture.

The implementation edits the same lifetime buffers registered under `Input.Bind.*`, immediately rebuilds the parsed scancode table and saves `ge007.ini`. No parallel binding database is introduced.

## Modern gamepad rebinding

Open `F10 -> Controls` and select one of the `Pad bind:` rows. Activate it, release any controller button that was already held, then press the new button.

The configurable Modern actions are:

- action/use;
- reload/cancel;
- crouch;
- next weapon;
- previous weapon;
- alternate action;
- start/pause.

The capture layer ignores the Guide/Home button because operating systems and controller drivers may reserve it before the game receives the event. Bindings persist in `ge007.ini` under `Input.ModernPadBind.*`. Resetting PC settings restores both keyboard and Modern gamepad binding defaults.

## Canonical commands

From MSYS2 MINGW64:

```bash
python tools_pc/ascension.py prepare
python tools_pc/ascension.py test
python tools_pc/ascension.py controllerdb
python tools_pc/ascension.py assets
python tools_pc/ascension.py build
```

Run the deterministic build/test pipeline without network activity:

```bash
python tools_pc/ascension.py all
```

Or use the developer playtest flow, which also performs a best-effort pinned controller-database refresh and then launches the built game:

```bash
python tools_pc/ascension.py play
```

The regression command runs every contract and writes `ascension-0.0.4-test-report.txt`. CI also retains build logs so compiler failures can be diagnosed without weakening a release gate.

## Automated qualification

The qualification gate includes:

- Windows latest with MSYS2 MINGW64;
- Linux with GCC 13;
- Linux with GCC 14;
- stack preparation and patcher idempotence;
- Python syntax checks;
- V2/V3/V4 control contracts;
- Universal Controller Layer contract;
- UI, Q Watch/runtime and mission/save-isolation contracts;
- `git diff --check`;
- ROM symbol generation;
- complete native compilation and executable-existence verification.

Automated success is necessary but not sufficient for input feel or unusual physical hardware. The release remains a test candidate until the manual matrix below is completed on the target Windows machine.

## Required manual smoke test

Before promotion, test at minimum:

1. Launch with no controller connected. Keyboard + mouse must behave exactly like the accepted checkpoint.
2. Frontend mouse pointer reaches all menu edges; LMB selects and RMB backs out.
3. Start Dam with Modern mouse and verify mouse feel is unchanged from the accepted checkpoint.
4. Open/close Q Watch twice and verify mouse look resumes immediately.
5. Open/close F10 twice and verify mouse look resumes immediately.
6. Connect an Xbox/XInput-compatible controller before launch. It should work without a manual mapping wizard.
7. Enable Modern + Modern twin-stick and test left-stick slow/full/diagonal movement.
8. Rotate with the right stick slowly around center and then full deflection; Precision should remain controllable and maximum turn available.
9. Hold LT and verify ADS right-stick speed is lower than hip-fire at the default 65%.
10. Test the default A/X/B/Y/LB/RB/RT/LT, Start and D-pad mappings.
11. Enable Southpaw and verify movement/camera sticks exchange roles cleanly; disable it and verify the default returns.
12. Enable trigger swap and verify LT/RT exchange aim/fire roles; disable it and verify the default returns.
13. Rebind at least Action and Crouch from F10, close F10 and verify the new gamepad buttons work immediately.
14. Relaunch and verify the gamepad mappings from the previous step persisted.
15. Rebind Forward to another keyboard key in F10, verify it immediately, relaunch and verify persistence.
16. Reset PC settings and verify keyboard and Modern gamepad bindings return to defaults.
17. Switch to Classic and verify its gameplay mapping still behaves as before.
18. Switch to Hybrid and verify its behavior still matches the checkpoint.
19. While the game is running, unplug the controller. Keyboard/mouse must remain usable and the game must not crash.
20. Reconnect the same controller while the game is running. It must be rediscovered without restarting the game.
21. If available, connect a generic USB/DirectInput controller that Windows can see. Test both launch-time detection and hot-plug detection.
22. On a generic controller, verify left/right sticks, D-pad, face buttons, shoulders/triggers and Start individually. A heuristic mapping is not considered accepted merely because the device opened.
23. If the generic controller uses the fallback, inspect the log for `AUTO-MAPPED unknown controller` and record its reported name/GUID if any control is wrong.
24. Connect a known controller after a skipped/non-gamepad HID device if available; it should still occupy the first playable logical controller slot rather than being shifted by the skipped device.
25. Open and close native Q Watch using controller, then immediately use mouse; ownership must remain clean in both directions.
26. Open/close F10 using mixed mouse/controller input and verify neither leaves stale camera movement.
27. Return to mission selector through F10 and verify selected save/profile remains intact.
28. Toggle All Missions off/on and verify no campaign progress is written.
29. Alt-Tab out/in during gameplay and verify there is no camera snap or stale controller look.
30. Play one complete mission while deliberately alternating keyboard/mouse and controller several times.

## Promotion rule

A green CI run proves source integration and deterministic contracts. It does not prove controller feel and cannot prove the semantic layout of every unknown HID device. 0.0.4 should move from test candidate to validated only after the Windows smoke-test matrix is played on real hardware and the existing mouse/Q Watch checkpoint behavior remains intact.
