# Ascension patch stack and subsystem ownership

This file is the mechanical map of the Ascension PC integration as of the 2026-09-15 playable Q Watch checkpoint.

The rule is simple: **order matters**. Several patchers intentionally anchor against output generated by earlier patchers. When a later patch reports a missing or ambiguous anchor, first verify that the exact stack order was used before editing code manually.

After the stack is installed, run the matching tests in the same conceptual order.

## Why the stack is patcher-first

Ascension is built on a decompilation/native-port codebase that can continue to receive upstream changes. The patcher-first approach gives the project three advantages:

1. the upstream-derived source stays easier to compare;
2. each feature has an explicit installer and an explicit regression contract;
3. an upstream conflict fails at an anchor instead of silently producing a half-integrated binary.

The downside is that a developer must understand the distinction between **repository source before integration** and **generated source after integration**. CI intentionally exercises the generation path on a clean checkout.

## Subsystem ownership

### 1. `port/src/input.c` — PC input router

This is the central SDL keyboard/mouse/gamepad source for PC controller state.

Important concepts:

- `mouseCaptureMode`: PC capture policy; checkpoint default is Quake-style click-to-lock behavior.
- `captureArmed`: remembers whether the user has armed gameplay capture.
- `mouseGrabbed`: actual SDL relative mouse state.
- `windowFocused`: focus gate.
- `mouseDX/mouseDY`: per-poll relative movement consumed by gameplay.
- `menuMode`: routes input away from gameplay direct-look and toward frontend cursor semantics.
- absolute frontend pointer path: writes GoldenEye's `cursor_h_pos/cursor_v_pos` from OS mouse position while the cursor is free.
- relative fallback menu path: retained for legacy/grabbed conditions.
- menu clicks: LMB -> native A/select; RMB -> native B/back.
- V3 direct look: gameplay camera motion bypasses the old N64 stick quantization for mouse camera only.

Do not globally wrap the entire mouse block with a condition that excludes Modern menus. An earlier regression did exactly that and killed native menu mouse control.

### 2. `src/game/bondview2.c` — native gameplay camera hook

Modern Controls V3 introduces the narrow direct-look integration here.

The key invariant is sign correctness: GoldenEye's vertical camera convention is opposite the ordinary desktop mouse convention. The Ascension direct-look path corrects that at the bridge so mouse-down means look-down by default.

If vertical look suddenly reverses after an upstream merge, inspect this hook before changing the generic SDL mouse delta sign in `input.c`, because changing the generic sign can break menus and aim-mode behavior simultaneously.

### 3. `port/src/optionsoverlay.c` — F10 systems layer

This is the PC-owned overlay. It should remain visually and logically separate from GoldenEye's native watch.

Responsibilities include:

- Q Branch systems UI;
- page/category navigation;
- mouse hit testing and slider drag;
- keyboard fallback;
- localized help text;
- F10 quick-return action;
- All Missions toggle;
- display/input/system settings.

Important invariant: F10 `Return to main menu` must call the narrow watch bridge only after confirmation. It must not implement a fake restart itself.

### 4. `src/game/options.c` — native Q Watch

This is GoldenEye's real watch logic, not a replacement overlay.

Checkpoint behavior:

- native watch page identity remains intact;
- Ascension adds presentation/chrome while retaining the stock watch machinery;
- the stock Abort Mission route remains a stock abort;
- the F10 convenience return uses a separate PORT bridge.

Two frontend transitions intentionally coexist:

**Stock Q Watch Abort Mission:**

```text
set_missionstate(MISSION_STATE_0)
bossRunTitleStage()
mission_failed_or_aborted = TRUE
deleteCurrentSelectedFolder()
```

**Ascension F10 convenience return:**

```text
solo-only guard
watch selection state clear
set_missionstate(MISSION_STATE_0)
mission_failed_or_aborted = FALSE
frontChangeMenu(MENU_MISSION_SELECT, FALSE)
bossRunTitleStage()
```

Never merge these paths just because they both leave a mission. They have different semantics.

### 5. `port/src/video.c` — SDL event shell

This owns top-level SDL window events.

The critical Q Watch regression came from the Escape event handler. Escape is also a normal GoldenEye Cancel binding. Before the runtime fix, the SDL shell always called `inputReleaseCapture()` on Escape outside F10. Closing the watch therefore also disarmed the gameplay mouse.

Checkpoint rule:

```text
Escape
  -> if F10 open: close F10
  -> else if native Q Watch active: do not release capture; let GoldenEye consume Cancel
  -> else: release PC mouse capture
```

The guard must execute **before** `inputReleaseCapture()`.

### 6. `port/include/ascension_watch.h` — narrow PORT bridge

Keep this header small. It exists to expose only the minimum bridge needed by PC-owned code:

- watch activity query;
- convenience return request.

Do not expand it into a general save/progression API.

### 7. `src/game/front.c` — native frontend availability

The All Missions feature belongs here only as a reversible availability policy. It must not write completion into save state.

If disabling All Missions fails to restore normal campaign gating, inspect the availability override ordering and its config value. Do not patch file save routines as a shortcut.

### 8. `port/src/ascension_locale.c` — localized PC copy

Current UI strings and contextual help for PT-BR and English live here. Keep technical option keys stable while improving visible copy.

| `test_watch_ui_final.py` | native watch identity, stock abort isolation, F10 convenience route semantics |
| `test_watch_runtime_fix.py` | Q Watch capture preservation and direct frontend return hotfix |

A new bug fix should normally add or strengthen the test nearest to the subsystem that failed.

## Idempotence contract

Every patcher used in the canonical stack should satisfy one of two outcomes on a tree where its feature is already present:

- return the exact same text; or
- explicitly report that no change is needed.

A patcher should never duplicate generated blocks.

When an old generator and a newer hotfix overlap, the safe entrypoint must recognize the newer state and preserve it. `apply_watch_ui_final_safe.py` contains this compatibility logic for the post-final-watch runtime fix.

## Anchor failure procedure

If a patcher says `expected exactly one anchor, found 0`:

1. confirm the patch order;
2. confirm the file is from the expected base revision;
3. search for the intended semantic block, not just one exact whitespace form;
4. check whether a newer patch already replaced it;
5. update the patcher's safe compatibility layer rather than hand-editing generated output;
6. add a regression test for the new source shape.

If it says `found 2` or more, stop. Duplication is more dangerous than a missing anchor because it can make the patch apply to the wrong control path.

## Windows CI detail

MSYS2's minimal PATH may not contain Git even though `actions/checkout` used Git for Windows earlier. Therefore the Windows validation workflow deliberately invokes:

```bash
"/c/Program Files/Git/bin/git.exe" diff --check
```

Do not replace this with bare `git diff --check` unless the workflow explicitly installs/exposes Git in the MSYS2 environment.

## Build boundary

After patching and tests:

```bash
python scripts/gen_romassets.py u
./build-pc.sh ntsc-final
```

A successful compile is necessary but not sufficient. Input-state bugs are frequently transition bugs, so the manual checkpoint smoke test in `docs/checkpoints/2026-09-15-watch-fixed.md` remains mandatory before promoting a control/menu/watch change.
