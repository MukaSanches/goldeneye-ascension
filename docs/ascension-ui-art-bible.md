# Ascension UI Art Bible — MI6 / Q Branch / Field

## Product rule
Ascension must look like a premium continuation of GoldenEye's own interface language, not a generic 2020s settings dashboard. Every screen starts from an in-world GoldenEye object or institution.

## Three visual spaces

### MI6 Classified Archives — front end / files
The native folders, reconnaissance thumbnails and save/progression logic remain the source of truth. Ascension frames them as an MI6 archive: restrained classified-document chrome, intelligence references, photographic evidence, file codes and archival typography. Do not replace folders with rounded app cards.

### Q Branch Systems — F10
F10 is a calibration instrument, not "Settings". Display, Input and Field parameters use dark technical surfaces, ivory text, aged brass/gold hierarchy and minimal status indicators. Controls must remain instantly understandable with mouse, keyboard or controller.

### Field — gameplay
Minimal intervention. GoldenEye's HUD/watch/gameplay own this space. Ascension input improvements must not become visual clutter.

## Palette
- Carbon black / near-black: equipment and archive framing.
- Warm ivory: primary readable text.
- Aged brass/gold: hierarchy, active state, 00/MI6 accent.
- Desaturated slate: secondary metadata.
- Restrained red: destructive/danger/alert only.
- Restrained institutional green: success/ready only.

No neon, cyberpunk, holographic blue, glassmorphism, large gradients, pill controls or mobile-style toggles.

## Shape language
Straight rules, fine borders, paper/photo edges, instrument ticks, archival stamps and compact technical blocks. Corners are mostly square. Animation is short and functional (roughly 100–220 ms): dossier lift/open, selection emphasis, terminal state change. No bouncing or ornamental motion.

## Typography
Use the game's existing typography where it creates identity: GoldenEye/mission headings, MI6 labels, dossier titles. Keep dense technical copy short. Avoid synthetic all-caps everywhere; hierarchy should come from placement and contrast, not shouting.

## AI-generated asset policy
AI imagery is allowed as production material, but it must be art-directed and post-treated so the final screen reads as 1990s intelligence material rather than generative art.

Preferred generated assets:
- reconnaissance landscapes and industrial exteriors without recognizable actors;
- aerial/satellite-style terrain plates;
- paper, folder, photographic and negative textures;
- technical-map backplates and abstract intelligence-room details;
- non-readable stamp/ink wear masks and analog photographic imperfections.

Avoid:
- actor likeness recreation;
- fake readable classified text inside generated pixels;
- modern vehicles/electronics accidentally appearing in 1995 material;
- sci-fi HUDs, cyberpunk screens or generic spy silhouettes;
- generated logos that imitate MGM/Rare/007 marks.

All readable text, MI6 codes, dates and UI labels are rendered by the game, never baked into AI images. This keeps localization sharp and prevents malformed text.

## AI asset master treatment
1. Generate clean 16:9 or 4:3 source plate with explicit 1989–1995 material culture.
2. Crop for the target UI aperture.
3. Reduce saturation and dynamic range slightly.
4. Add restrained 35mm/print grain and tiny optical softness.
5. Apply photographic paper/scan character only where the asset is meant to be a physical photo.
6. Add all codes, captions, redactions and classification marks procedurally in-engine.
7. Review at 640x480 and 4K; the composition must survive both.

## Mission asset grammar
- Dam: aerial reconnaissance, concrete infrastructure, cold mountain atmosphere.
- Facility: industrial surveillance, chemical-plant geometry, technical plan fragments.
- Runway: airfield reconnaissance, runway markings, vehicle/aircraft infrastructure without hero imagery.
- Surface: snow reconnaissance, satellite/terrain cues, Soviet-era utility structures.
- Bunker: underground technical plans, communications/intelligence-room material.
- Silo: strategic-industrial architecture, launch infrastructure, warning-document texture.
- Frigate: maritime reconnaissance, naval technical imagery.
- Surface II / Bunker II: reuse the established location grammar with later-operation markings rather than inventing a new style.
- Statue: night reconnaissance, monumental urban/industrial texture.
- Archives: paper intelligence, records, shelves, document photography.
- Streets: urban surveillance and route-map language.
- Depot: rail/warehouse reconnaissance.
- Train: rail intelligence, carriage diagrams, route/operation markings.
- Jungle: field reconnaissance, humid film response, map overlays.
- Control: hardened technical facility, command-room documentation.
- Caverns: underground survey/industrial geology language.
- Cradle: antenna/structure reconnaissance and high-altitude technical photography.

## Interaction rules
- Gameplay: relative/raw mouse may control camera.
- Any GoldenEye menu: mouse controls the native front-end pointer; direct-look never owns it.
- Left click: native Select/A.
- Right click: native Back/B.
- F10: hover selects, click activates, slider drag is continuous, category labels are click targets, wheel scrolls, WASD/arrows remain available.
- Device changes never require a settings switch.

## Preservation rules
UI work must not alter mission scripts, AI, damage, weapons, save formats, progression, collision or difficulty. Native file-select logic remains authoritative even when presentation is enhanced.

## Acceptance bar
A screenshot without the Ascension name should still be identifiable as GoldenEye. A screenshot with all GoldenEye branding removed should still look like a coherent 1995 British intelligence/field-technology interface, not a template or AI mockup.
